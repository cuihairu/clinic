# 管理端（web）

`web/` 是医馆日常运转的主工作台：Ant Design Pro + Umi（@umijs/max）工程，Node.js 24 / pnpm，中文界面。

界面原型（设计稿 · 数据为虚构演示，石墨×古金主题取自品牌 logo，另有松烟绿 / 朱砂 / 黛蓝三套可切换主题色）：

更多分页原型（接诊诊疗单 / 每日报表 / 卡项 / 订单 / 广告屏 / 外观设置）见[文档站首页产品预览](./index.md#产品预览)与仓库 `docs/design/mockups/`。

## 运行方式

```bash
cd web
pnpm install
pnpm dev     # dev 模式：MOCK=none，代理到本机服务端
```

- 开发地址 `http://localhost:8000`，`/api` 代理到 `http://127.0.0.1:2347`（`config/proxy.ts`）。
- `pnpm build` 产出 `dist/`，交由 Nginx 托管；`pnpm lint` 代码检查、`pnpm jest` 单测。

## 工程结构

| 位置 | 内容 |
| ---- | ---- |
| `config/config.ts` | 站点标题、布局（mix）、国际化（zh-CN 默认）、插件与 openAPI 配置 |
| `config/routes.ts` | 路由表（页面注册） |
| `config/proxy.ts` | dev / test / pre 环境代理 |
| `src/pages/` | 页面组件，按业务域分目录 |
| `src/services/ant-design-pro/` | 接口定义（与服务端 `/api/v1/**` 一一对应） |
| `src/access.ts` | 运行时权限：`canAdmin`（管理层）、`canUser`（已登录） |
| `src/app.tsx` | 启动时拉取当前用户、未登录重定向、水印 |
| `src/requestErrorConfig.ts` | 从 `localStorage.jwt` 注入 `Authorization: Bearer`，统一错误提示 |
| `src/locales/` | 菜单等文案多语言 |

## 页面与任务对照

登录后默认落地 **每日报表**（`/dash/day`）。医馆主流程沿「顾客建档 → 接诊（诊断） → 卡项 → 复盘回访」展开，按任务找页面：

### 预约系统（/appointment）

主流程「预约 → 到店接待 → 发起接诊」的第一环。列表工作台 + 按日时段网格两种视图（对齐 `docs/design/mockups/admin-booking.html`）。

| 路径 | 页面 | 做什么 |
| ---- | ---- | ---- |
| `/appointment/schedule` | 排班视图 | 按日看医师×时段占用（9:00–18:00 整点网格，列为当日出现的医师 + 未指派）：空格虚线「可预约」，有约显示顾客/项目与状态标，待到店格内一键「接待」（0→1）；右侧今日统计（总数/已到店/待到店/已取消），日期前后翻页与「今天」 |
| `/appointment/query` | 预约排班 | 今日/全部切换 + 状态 tab（待到店/已接待/已取消带计数）；行操作：到店接待（0→1）、取消（0→9）、已接待后「发起接诊」跳 `/treat/create?customerId=`、已取消可删 |
| `/appointment/create` | 新建预约 | 按手机号定位顾客（未建档提示先建档）→ 时段（日期时间 + 时长 30/60/90 分钟）→ 项目/员工/备注选填；提交发带时区偏移的时间串（服务端 Jackson 默认 UTC，无偏移会平移 8 小时） |

排班口径：同一时段不冲突校验（演示边界），一格落多条时取第一条并标 `+N`；时段网格只覆盖 9:00–18:00 整点，非整点开始的预约会归到所在小时格。

### 收费结算（/billing）

自助机/前台单据的收款环节（对齐 `docs/design/mockups/admin-billing.html` 的结算台形态）。

| 路径 | 页面 | 做什么 |
| ---- | ---- | ---- |
| `/billing/settle` | 结算台 | 左侧待结算队列（订单状态 0/1，`自助机`/`前台` 来源标签）+ 最近结算记录（每条可补打小票）；选单后选支付方式收款：储值卡（显示实时余额，余额不足可填额充值后一并收款）、微信、支付宝、现金、次卡（显示本单卡项有效余次，选中即扣 1 次、实收记 0）；收款成功订单转「已完成」并落结算单 |

结算口径：实收取订单价格快照，储值支付自动扣减余额（流水合计）；次卡抵扣扣持卡余 1 次、实收记 0，并在同一事务落核销流水（顾客档案持卡栏可查）；微信/支付宝仅记录支付方式（无真实收银通道）；小票走服务端套打 `GET /api/v1/print/receipt/{settlementId}`（80mm HTML，收款成功后可打印、最近结算可补打）；处方饮片行进结算裁定不做——收费以卡项订单结算为准，处方计价为试算/提示口径。

### 处方系统（/prescription）

| 路径 | 页面 | 做什么 |
| ---- | ---- | ---- |
| `/prescription/create` | 开方 | 按手机号定位顾客 → 「套用模板」按病症一键带出药味/剂数/用法（可选）→ 写药味（药名/克数/特殊煎法，可增删行）+ 类型（汤剂/膏方，膏方选收膏方式）+ 剂数 + 用法 + 备注，选填开方医师 |
| `/prescription/query` | 处方查询 | 已开处方笺一览（顾客/医师/药味/剂数/类型/代煎/膏方状态/用法/开方时间/实时计价），「详情」抽屉看整方药味与计价明细、代煎与膏方各自流转领取，可删除 |
| `/prescription/templates` | 病症模板 | 病症处方模板库维护页：新建/编辑（药味行内增删）/删除/上架开关，病症名唯一；模板只存建议值，套用后随处方自由增减不写回 |
| `/prescription/herbs` | 药材字典 | 处方计价比价依据的维护页：收录/改价/删除，名称唯一精确匹配，价格为每克分价（页内以元展示） |

药材名为自由文本；配伍审方（十八反/十九畏）与实时计价已实装——开方页随写随查（审方提示不拦截；计价按药材字典精确同名比价、未收录药名不计费）；代煎已实装——开方页勾选「代煎 N 袋」（袋数=剂数，服务费 ¥3/袋 仅提示），查询页列表出代煎状态、详情抽屉流转领取（待煎→可取→已取）；膏方已实装——开方页类型选「膏方」并选收膏方式（炼蜜/清膏/糖膏/阿胶收膏，可清空），开方落「待制作」（膏方按料计不勾代煎），查询页列表出膏方状态、详情抽屉流转（待制作→可取→已取）；病症模板已实装——开方页「套用模板」下拉（仅上架模板），带出后一切可改。

## 权限与角色

- `canAdmin`：管理端创建 / 查询员工入口（对应服务端 `role < 10` 的管理层）；
- `canUser`：签到与今日考勤入口（任何已登录员工）；
- 服务端接口层暂未强制方法级权限，页面级隐藏是当前主要控制手段。

## 前端遗留项（如实说明）

- 站点标题当前为模板值 `Youngs.fun`（`config/config.ts`），未改为项目名；
- `config/oneapi.json` 仍为脚手架模板 schema（含 `/api/rule` 等模板端点），驱动 openAPI 插件生成 `src/services/ant-design-pro/api.ts` 与 `typings.d.ts`（其中 `currentUser` 等已手改指向真实后端接口）；
- `manifest.json` / PWA 名称仍是脚手架默认值。

> 已清理：脚手架残留页面 `src/pages/Welcome.tsx`、`Admin.tsx`、`TableList/`（不在路由，无引用）；petstore 示例服务 `src/services/swagger/`（`config.ts` openAPI 第二入口一并移除）；卡项占位页 `/item/spread`、`/item/update`（表单实为 `createItem` 建新卡项的误用隐患，已连同路由移除，编辑统一走 `/item/create?itemId=`，`updateItem` 服务函数保留备用）。
